# CareerConnect — Issue #50: Two-Factor Authentication

Open · Future Enhancement

User Story #11 · Issue #50

I reviewed [GitHub issue #50](https://github.com/Ionnerss/CareerConnect/issues/50?utm_source=chatgpt.com), the current `dev` branch (`231ff2c`), and Supabase's MFA documentation.

The feature has not been implemented yet. CareerConnect currently supports email/password authentication, but it has no authenticator-app enrollment, verification challenge, or MFA-aware authorization.

The user story states:

> As a user, I want to enable two-factor authentication using an authenticator app so that someone who obtains my password cannot access my protected account data without the second factor.

One important distinction: adding a six-digit code screen is not sufficient security. Supabase can issue a valid `aal1` session immediately after password authentication. We must also prevent that session from accessing protected account data when the user has enabled MFA.&#x20;

## 4. What successful implementation looks like

| Scenario                                                     | Expected behavior              |
| ------------------------------------------------------------ | ------------------------------ |
| User without MFA logs in                                     | Normal login                   |
| User enables MFA                                             | QR setup and code verification |
| MFA-enabled user enters correct password                     | Second factor required         |
| User enters correct authenticator code                       | Access granted                 |
| User enters incorrect code                                   | Access denied, retry allowed   |
| User directly opens a protected URL before MFA               | Redirect to verification       |
| User directly queries protected data using an `aal1` session | Request denied                 |
| User disables MFA after required verification                | Normal login restored          |

The direct-data-access test is especially important. A frontend redirect alone would not satisfy the user story's security objective.

## Step 1 — Configure Supabase for two-factor authentication

Before modifying the login page, we need to make sure Supabase can enroll and verify authenticator-app codes.

I checked CareerConnect's `dev` configuration and found something important.

Local TOTP authentication is currently disabled.

In `supabase/config.toml`, the settings are:

```
[auth.mfa.totp]
enroll_enabled = false
verify_enabled = false
```

These settings control your local Supabase environment, not necessarily the hosted project your application currently uses.

Supabase's hosted projects support TOTP MFA by default, but the feature can be controlled through authentication settings.&#x20;
